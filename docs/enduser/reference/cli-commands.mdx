The `@hoox-sh/hoox-cli` tool (**0.16.0**) manages workspace bootstrap, Cloudflare provisioning, worker deploy, secrets, monitoring, and repair. The binary is also available as **`hx`**.

</Frame>

<Frame caption="Help tour: version, logs, TUI, doctor">
  <img src="/docs/images/gifs/cli-help-tour.gif" alt="Animated CLI help screens" />
</Frame>

Per-group stills: [Interface gallery](/docs/enduser/guides/screenshots#cli).

Install: `bun add -g @hoox-sh/hoox-cli`. Recommended bootstrap: `hoox onboard`. Prefer CLI commands over raw Wrangler for day-to-day ops. Agents can run the same commands through the [Hoox MCP server](/docs/devops/mcp) (`bun run mcp` from a checkout — the MCP package is private and is not published to npm).

**0.16.0 surface:** monorepo auto-detect + remember (run `hx` from any cwd), Linear Rail banner (`◆ H · O · O · X`), secret sync modes (`--system` / `--required`), `hoox workers catalog` / `enable` / `disable`, `hoox pyne` for **pyne-worker**, operator security plane (`doctor --security`, `tunnel check`). Global UX: `--json` task-result arrays (no clack spinner mix), `--quiet` (no stdout), `--no-color` / `NO_COLOR` / `TERM=dumb`, completion footers, “did you mean …”, sectioned help. Kill-switch show/on/off covers both canonical KV keys.

Older CLI releases (0.8–0.13) are not current. See [`packages/cli/CHANGELOG.md`](https://github.com/hoox-sh/hoox/blob/main/packages/cli/CHANGELOG.md) for history.

## 📍 Workspace resolution (any cwd)

On every invocation the CLI resolves a monorepo root, remembers it, and
`chdir`s into it so relative paths (`wrangler.jsonc`, `workers/`, …) work even
when you launch `hx` from `~/Videos` or another project.

**Order:**

1. **`HOOX_REPO`** — explicit absolute path
2. **Walk up from cwd** — local checkout markers
3. **Remembered path** — `~/.hoox/config/monorepo.json`
4. **Global clone** — `~/.hoox/repo` (`hoox doctor --fix-runtime`)

**Monorepo markers:** `packages/cli/package.json` plus one of `wrangler.jsonc`,
`wrangler.jsonc.example`, `workers/`, or `.gitmodules`.

```bash
# Discover once from the monorepo
cd ~/Git/hoox && hoox doctor

# Use from anywhere
cd ~/Videos && hx check health
```

| Env / file | Role |
| ---------- | ---- |
| `HOOX_REPO` | Force monorepo root |
| `HOOX_HOME` | Base for `~/.hoox` layout (config, data, global repo) |
| `HOOX_CLI_SILENT=1` | Suppress “using monorepo at …” stderr line |
| `~/.hoox/config/monorepo.json` | Persisted `{ "root", "updatedAt" }` |

`hoox doctor` prints **Remembered**, **Runtime root**, and **Source**
(`env` | `cwd` | `remembered` | `global` | `none`).

## 🗺️ Global Flags

These options are registered globally and can be appended to any command:

| Flag         | Description                                                          | Example                         |
| :----------- | :------------------------------------------------------------------- | :------------------------------ |
| `--json`     | Machine-parseable JSON. Task-runner commands (`deploy all`, `check setup`, `check health`, …) write a **task-result array** (`title`, `ok`, `ms`, optional `value` / `error` / `details`). | `hoox deploy all --json`        |
| `--quiet`    | Prints nothing (no headers, tables, or task summary).                | `hoox deploy all --quiet`       |
| `--no-color` | Disable ANSI color output (also: `NO_COLOR=1` env var, `TERM=dumb`). | `hoox --no-color check health`  |
| `--help`     | Prints complete parameter and option listings.                       | `hoox infra d1 --help`          |
| `--version`  | Outputs active CLI package build version (`0.16.0`).                 | `hoox --version`                |
| `-y, --yes`  | Skip confirmation prompts (where supported).                         | `hoox repair rebuild --yes`     |

## 🚀 Key Commands Detail & Examples

### A. Onboarding (Start Here)

```bash
# Recommended: one-shot full bootstrap (collects credentials, provisions, deploys)
hoox onboard
# aliases: hoox bootstrap, hoox quickstart

# Non-interactive one-shot
hoox onboard --token cfut_xxx --account xxx --preset full

# Step-by-step (more control)
hoox init        # Write wrangler.jsonc, collect integration secrets
hoox setup       # Mesh keys, D1 schema, secrets, dashboard

# Self-hosted (no Cloudflare): print VPS / Docker path and exit
# Does not write wrangler.jsonc
hoox init --self-hosted

# Verify the system
hoox check setup
hoox check prerequisites
```

### B. Local Development

```bash
# Start all workers in a Docker container stack
hoox dev start --runtime docker

# Start all workers natively via wrangler dev
hoox dev start --runtime native

# Start a single worker
hoox dev worker trade-worker

# Start the Next.js dashboard dev server
hoox dev dashboard
# OR (equivalent):
hoox dashboard dev
```

### C. Edge Provisioning & Deployment

```bash
# Provision all databases, buckets, and queues on your Cloudflare account
hoox infra provision
hoox infra provision --dry-run

# Deploy the entire microservices stack in sequence
hoox deploy all --auto

# JSON: task-result array on stdout. Quiet: no stdout.
hoox deploy all --json
hoox deploy all --quiet

# Preview without executing
hoox deploy all --dry-run

# Deploy a single worker
hoox deploy worker trade-worker

# Build and deploy the Next.js dashboard
hoox dashboard deploy --rebuild
# OR (equivalent):
hoox deploy dashboard --rebuild
```

### D. Health Checks & Monitoring

```bash
# Check all worker health endpoints (the single source of truth)
hoox check health

# Try to auto-fix any issues found
hoox check health --fix

# Auto-repair common local issues (preview first)
hoox check fix --dry-run
hoox check fix

# Audit active trade history table
hoox monitor trades 25

# Emergency Halt: halt all trade signals globally
hoox monitor kill-switch show
hoox monitor kill-switch on
hoox monitor kill-switch off

hoox monitor queue-depth
hoox monitor analytics summary
hoox monitor analytics errors --hours 24
```

### E. Secrets & Keys Management

Canonical trade-worker exchange secrets are **`EXCHANGE_KEY_BINDING`** and **`EXCHANGE_SECRET_BINDING`**. `hoox secrets set` requires the worker name and prompts for the value (hidden stdin). There is no third positional argument.

```bash
# Set a Cloudflare Worker secret (live exchange keys)
hoox secrets set trade-worker EXCHANGE_KEY_BINDING
hoox secrets set trade-worker EXCHANGE_SECRET_BINDING

# List secrets for a worker
hoox secrets list trade-worker

# Sync mesh/system secrets only (INTERNAL_KEY_BINDING, WEBHOOK_*, …)
hoox secrets sync --system
# Alias: hoox secrets sync --required

# Sync all declared secrets from .dev.vars
# Reports partial results: synced / skipped (placeholders) / failed
hoox secrets sync

# Generate internal auth keys
hoox keys generate

# List existing keys
hoox keys list
```

### F. Workers catalog

The shared worker catalog is the source of known isolates and default enabled flags. `enable` / `disable` write `workers.<name>.enabled` in the root `wrangler.jsonc`. Missing catalog workers are seeded on enable.

```bash
hoox workers list
hoox workers catalog
hoox workers enable trade-worker agent-worker
hoox workers disable web3-wallet-worker email-worker
hoox workers catalog --json
```

### G. Database Administration

```bash
# Query the total sum of fees paid today across Bybit
hoox db query "SELECT SUM(fee) FROM trades WHERE created_at >= date('now')" --remote
```

### H. PYNE (pyne-worker)

```bash
hoox pyne health
hoox pyne run ./strategy.pine --mode auto
hoox pyne scripts list
hoox pyne scripts get <id>
hoox pyne scripts deploy ./strategy.pine --id my-strategy
hoox pyne scripts delete <id>
hoox pyne cron jobs
hoox pyne cron run
hoox pyne feed refresh
hoox pyne ingest -- --symbol BTCUSDT --timeframe 1d
hoox pyne sync-vendor && hoox pyne deploy
```

Auth: `--api-key`, `PYNE_API_KEY` / `API_KEY`, or `workers/pyne-worker/.dev.vars`.
URL: `--url`, `PYNE_WORKER_URL`, or `https://pyne-worker.<subdomain_prefix>.workers.dev`.

### I. TUI

```bash
hoox tui
hoox tui --fps 30 --no-mouse
hoox tui --remote --token "$HOOX_API_TOKEN"
hoox tui --api-url https://mgmt.example.com --token "$HOOX_API_TOKEN"
hoox tui --debug
# Escape hatch (not recommended):
hoox tui --remote --allow-insecure
```

Remote mode requires Bearer (`--token` / `HOOX_API_TOKEN`), Cloudflare Access service-token env, or `--allow-insecure`.

### J. Update (git, not npm)

`hoox update` pulls git. It does **not** self-update the CLI from npm.

```bash
hoox update              # git pull of the main repo
hoox update d1-worker    # update that worker's submodule from its remote
hoox update wrangler     # update wrangler to the latest version
```

To install a newer CLI: `bun add -g @hoox-sh/hoox-cli`.

### K. Performance Measurement

```bash
# Send 50 synthetic probes and report p50/p95/p99 per-hop latency
hoox perf fastpath run --n 50

# Continuous probing for 60 seconds
hoox perf fastpath tail --duration 60

# Query past probe events
hoox perf fastpath report --from 1h
```

### L. Self-Healing & Diagnostics

```bash
# Run a full workspace system audit
hoox repair check
hoox repair check --install-deps --no-typecheck

# Verify worker health (the single source of truth)
hoox check health

hoox doctor
hoox doctor --security
hoox tunnel check
```

## Older releases

Commands such as `hoox onboard`, top-level `hoox secrets` / `hoox keys`, `hoox perf fastpath`, and `hoox dashboard` landed in 0.8.x. Shared formatters (`--no-color`, “did you mean”, completion footers) landed in 0.9.x. Linear Rail, monorepo remember, and quieter secrets checks landed later. **Current CLI is 0.16.0** — do not treat 0.9 as current.

Replacements still in force:

- `hoox monitor status` → `hoox check health`
- `hoox workers status` → `hoox check health`
- `hoox dashboard update-urls` → `hoox deploy update-internal-urls`

Full notes: [`packages/cli/CHANGELOG.md`](https://github.com/hoox-sh/hoox/blob/main/packages/cli/CHANGELOG.md).
